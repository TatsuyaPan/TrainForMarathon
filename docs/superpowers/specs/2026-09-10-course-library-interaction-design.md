# 课程库与课程编辑器交互设计

**日期：** 2026-09-10
**状态：** 待用户最终复核
**范围：** Web 课程库、课程结构展示、课程新建/编辑/复制/导入

**领域与 DSL 规范：** [课程库与 Workout DSL 重构设计](./2026-09-10-course-library-dsl-design.md)

## 1. 设计目标

本交互设计将课程库从“展示 DSL 的静态列表”升级为可阅读、可管理、可编辑的训练课程工作台。设计吸收：

- Garmin 的彩色训练结构预览、清晰步骤卡片、循环容器和移动端聚焦编辑；
- COROS 的课程信息集中编辑、桌面端紧凑步骤卡片、排序/编组和固定汇总；
- 当前产品的浅色主题、Daniels 强度色阶和可递归 Workout 模型。

界面不是 DSL 的第二套模型。每个用户操作都必须直接修改 Workout 草稿，DSL 由草稿即时序列化；DSL 导入则先解析成同一 Workout 草稿。任何无法被 DSL 表达的界面状态都不得保存。

## 2. 交互原则

1. **结构先于源码。** 默认展示训练步骤，DSL 放在次级折叠区。
2. **一个编辑器覆盖所有入口。** 新建、编辑、复制和导入共享组件与校验。
3. **渐进披露。** 列表看摘要，展开看结构，点击步骤才进入字段编辑。
4. **上下文编辑。** 只显示当前步骤类型允许的字段，不让用户制造非法组合。
5. **草稿隔离。** 保存前只修改深拷贝草稿，取消不会污染课程库。
6. **桌面与移动同能力。** 桌面可以拖拽，移动端必须有明确的移动按钮作为等价操作。
7. **颜色不是唯一信号。** 强度必须同时用颜色、文字和形状/图标表达。
8. **嵌套可读。** 深层循环用层级标识和边框表达，不无限压缩内容宽度。
9. **错误靠近来源。** 表单错误显示在字段附近，DSL 错误显示行、列和修复提示。
10. **汇总实时可信。** 只展示模型能够确定的距离和时间，不跨单位伪造精确值。

## 3. 信息架构与路由

```text
/library
  课程库列表
  ├─ 新建课程 → /library/new
  ├─ 导入课程 → 导入对话框 → /library/new?source=import
  ├─ 编辑自定义 → /library/:id/edit
  ├─ 复制内置 → /library/new?source=copy&course=:id
  └─ 复制自定义 → /library/new?source=copy&course=:id

/library/new
  统一课程编辑器（新建/导入/复制草稿）

/library/:id/edit
  统一课程编辑器（已有自定义课程草稿）
```

URL 只表达入口，不把整个草稿放进 query。导入或复制产生的草稿通过页面级临时状态传递；直接刷新而草稿不存在时，安全返回课程库并提示重新开始。

## 4. 课程库页面

### 4.1 页面线框

```text
┌──────────────────────────────────────────────────────────┐
│ 课程库                         [导入课程] [＋新建课程]    │
│ 选择、复制或创建适合自己的训练课程                        │
├──────────────────────────────────────────────────────────┤
│ [E] [M] [T] [I] [R] [ST] [混合]                         │
├──────────────────────────────────────────────────────────┤
│ 我的课程                                                  │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ T  8 分钟阈值跑 × 6                    自定义        │ │
│ │ 乳酸阈能力 · 48min 主训练 · 9min 恢复                │ │
│ │ ▂ █ ▂ █ ▂ █ ▂ █ ▂ █ ▂ █ ▂                         │ │
│ │ [展开步骤]              [编辑] [复制] [更多]         │ │
│ └──────────────────────────────────────────────────────┘ │
│                                                          │
│ 内置课程                                                  │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ I  亚索 800                              内置        │ │
│ │ ...                                      [复制使用]  │ │
│ └──────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

### 4.2 顶部操作

- “新建课程”是主操作，使用实心主按钮；
- “导入课程”是次操作，使用描边按钮；
- 窄屏时两者保持可见，不收入省略菜单；
- 分类筛选使用当前 Daniels 色阶，但选中态还需有边框或勾选标识；
- 首版不增加搜索、排序和批量操作。

### 4.3 分区与空状态

- 自定义课程和内置课程分区展示；
- 当前分类没有自定义课程时，显示“还没有自定义课程”及“新建/导入”入口；
- 当前分类没有任何课程时，不显示空白页面；
- 存储读取失败时显示错误状态和“清理无效本地数据”，内置课程仍然可用。

## 5. 课程卡片

### 5.1 默认摘要

卡片默认只呈现能帮助选择课程的信息：

- 分类标签；
- 展示标题；标题为空时使用训练目的；
- 内置/自定义来源；
- 必填训练目的；
- 可选课程备注的一至两行摘要；
- 已知总距离、已知总时间、主训练容量和恢复量；
- 彩色结构预览；
- 展开按钮和主要操作。

DSL 不在默认摘要中展示。

### 5.2 操作优先级

内置课程：

- 主操作：“复制使用”；
- 次操作：“展开步骤”；
- 更多：“查看 DSL”。

自定义课程：

- 主操作：“编辑”；
- 次操作：“展开步骤”“复制”；
- 危险操作：“删除”，放入更多菜单并二次确认。

卡片整体不绑定编辑跳转，避免用户展开步骤时误进入编辑器。

### 5.3 展开内容

展开后按 WU、MS、CD 显示结构树。不存在的 WU/CD 不显示空容器。每个阶段显示阶段名称、阶段汇总和递归步骤。

原始 DSL 位于步骤树之后的“查看 DSL”折叠区，提供复制按钮。复制失败时提供可选中文本，不弹出阻塞式 prompt。

## 6. 结构预览

### 6.1 目的

结构预览用于快速识别课程节奏，例如“热身—六组阈值/恢复—冷身”，不是编辑控件，也不是独立数据源。

### 6.2 映射规则

| Workout 内容 | 预览表现 |
| --- | --- |
| WU 跑步步骤 | 对应强度颜色，附热身起始形状 |
| MS 跑步步骤 | 对应目标强度颜色 |
| RecoveryStep | 浅蓝灰、较低高度 |
| RestStep | 灰色、最低高度 |
| CD 跑步步骤 | 对应强度颜色，附冷身结束形状 |
| RepeatBlock | 展开重复节奏或压缩为“×N”块 |

高度主要表示强度类别，不承诺生理负荷的精确比例。宽度只在同单位步骤之间按负荷比例计算。

### 6.3 混合单位

当课程同时包含时间和距离，且缺少运动员配速上下文时：

- 不把分钟与公里直接相加；
- 预览使用等宽步骤；
- 汇总分别显示已知时间和已知距离；
- 标注“混合单位，完整耗时需结合个人配速估算”。

### 6.4 大循环保护

- 可视化展开设置最大块数；
- 超过上限时以“代表性节奏 + ×N”压缩显示；
- 压缩不改变实际 AST 和汇总；
- 预览组件不能为绘制而创建数千个 DOM 节点。

## 7. 递归步骤树

### 7.1 普通步骤

```text
┌ T 主训练 ─────────────────────────────────────────────┐
│ 8 分钟 · 乳酸阈配速 · RPE 8                           │
│ 保持动作放松                                           │
└────────────────────────────────────────────────────────┘
```

显示顺序固定为：类型 → 负荷 →主目标 → 辅助 RPE → 坡度 → 备注。

### 7.2 循环

```text
┌ 重复 6 次 ─────────────────────────────────────────────┐
│ 1  主训练   8 分钟 · T                                 │
│ 2  恢复     90 秒 · 慢跑                               │
└────────────────────────────────────────────────────────┘
```

循环容器必须明显包住子步骤，不能只显示一行文本。循环摘要显示一次循环的结构和完整重复次数。

### 7.3 嵌套循环

- 第一、二层使用缩进和连接线；
- 第三层及以上保持相同最小左边距，改用“层级 3”等标签；
- 每层循环均可独立折叠；
- 折叠状态仅属于 UI，不写入 Workout 或 DSL；
- 展示组件以递归组件实现，不把 AST 展平成不可逆文本。

## 8. 导入交互

### 8.1 对话框

```text
┌ 导入单条课程 ───────────────────────────────┐
│ 粘贴完整 Workout DSL                         │
│ ┌─────────────────────────────────────────┐ │
│ │ GOAL:乳酸阈能力                         │ │
│ │ WU:15min@P3:10-3:30/km(E)               │ │
│ │ MS:6x(8min@P3:45-4:00/km(T)+90s@jog)    │ │
│ │ CD:10min@P3:10-3:30/km(E)               │ │
│ └─────────────────────────────────────────┘ │
│ 错误信息/解析摘要/配速版说明                  │
│                         [取消] [解析并编辑]  │
└──────────────────────────────────────────────┘
```

### 8.2 状态流

```text
empty → typing → parsing
                  ├─ invalid → error → typing
                  └─ valid → draft preview → editor
```

- 输入为空时“解析并编辑”禁用；
- 解析失败时保留原文并选中/标记错误位置；
- 解析成功显示阶段数、步骤数、循环数和基础汇总；
- 进入编辑器前不写 localStorage；
- 一次只接受一个完整 Workout；检测到第二个 `GOAL` 或多份文档时拒绝；
- 缺少 `WORKOUT/<version>` 时使用平台当前最新版解析器，解析失败后不猜测或回退其他版本；
- 标题和课程备注缺失不阻止导入，`GOAL` 缺失或为空必须拒绝；
- **档位写法与配速写法都接受**：`MS:6x(8min@T+90s@jog)` 与 `MS:6x(8min@P3:45-4:00/km+90s@jog)` 都在 v1 语法内，
  对话框说明两者都能导入，用户不需要先换成某一种写法；
- 两种写法含义不同而不是互相等价：档位写法导入成强度档位，配速写法导入成**明确配速**（`pace-range`），
  摘要下面据此补一行说明——含档位时说明「配速写法可以按当前能力导出成配速」，只有配速时说明
  「明确配速原样导入，不会被换算成 E/M/T/I/R 档位」（见 §19.4）；
- 配速写法是**派生投影**，不会凭空反推档位：导入配速写法得到的课程只含明确配速。

## 10. 编辑器状态模型

```ts
type EditorMode = "create" | "edit" | "copy" | "import";

interface CourseEditorState {
  mode: EditorMode;
  originalCourseId?: string;
  draft: LibraryCourseDraft;
  selectedPath: number[] | null;
  dirty: boolean;
  submitting: boolean;
  errors: FieldError[];
}
```

展示标题取 `draft.workout.title || draft.workout.goal || "新建课程"`，只用于界面显示，不回写为默认标题。

- `draft` 是唯一编辑源；
- `selectedPath` 指向阶段或循环内的分部路径；
- UI 折叠状态、选中状态和拖拽状态不进入 `draft`；
- 每次结构操作后重新运行轻量校验和汇总；
- 保存时运行完整课程与 Workout 校验。

## 11. DSL 与界面映射

### 11.0 课程头部

| DSL | AST | 界面 |
| --- | --- | --- |
| `WORKOUT/1` | `Workout.dslVersion = 1` | 高级信息中的可选版本声明 |
| `TITLE:...` | `Workout.title?` | 可选课程标题 |
| `GOAL:...` | `Workout.goal` | 必填训练目的 |
| `NOTE:...` | `Workout.note?` | 可选课程备注 |

缺少版本声明时使用平台当前最新版解析器。缺少标题或备注时保持未设置，不生成占位文本；缺少或留空 `GOAL` 时禁止保存和导入。

### 11.1 阶段

| DSL | AST | 界面 |
| --- | --- | --- |
| `WU:` | `WorkoutPhase.role = warmup` | 热身阶段容器 |
| `MS:` | `WorkoutPhase.role = main` | 主训练阶段容器 |
| `CD:` | `WorkoutPhase.role = cooldown` | 冷身阶段容器 |

MS 始终存在。用户添加/删除热身或冷身时，实际添加/删除对应 `WorkoutPhase`，而不是在步骤上写隐藏 phase 字段。

### 11.2 步骤类型

| 界面选择 | AST | DSL |
| --- | --- | --- |
| 热身跑步 | WU 中的 `RunStep` | `WU:10min@E` |
| 主训练跑步 | MS 中的 `RunStep` | `MS:8min@T` |
| 主动恢复 | `RecoveryStep` | `90s@jog` |
| 被动休息 | `RestStep` | `2min@rest` |
| 冷身跑步 | CD 中的 `RunStep` | `CD:10min@E` |

当用户把普通跑步步骤移动到另一个阶段时，AST 中只有父阶段发生变化，序列化后的阶段行随之变化。恢复与休息移动后仍保持自身类型。

### 11.3 持续方式

| 界面 | AST | DSL |
| --- | --- | --- |
| 时间 10 分钟 | `{ type: time, seconds: 600 }` | `10min` |
| 时间 90 秒 | `{ type: time, seconds: 90 }` | `90s` |
| 距离 800 米 | `{ type: distance, meters: 800 }` | `800m` |
| 距离 1.5 公里 | `{ type: distance, meters: 1500 }` | `1.5km` |

被动休息选择器不显示“距离”。切换时间/距离时使用该类型的合理默认值，不把旧数值按不同单位直接沿用。

### 11.4 主目标

| 界面选择 | DSL |
| --- | --- |
| Daniels E/M/T/I/R/ST | `@E` 等 |
| 自定义配速范围 | `@P4:45-5:00/km` |
| 最大心率百分比 | `@HR65-78%max` |
| 储备心率百分比 | `@HR60-70%hrr` |
| 绝对心率 | `@HR145-160bpm` |
| RPE 主目标 | `@RPE7` |

选择主目标类型后只显示对应输入。一个跑步步骤只能选择一个主目标；如果主目标不是 RPE，可另外填写辅助 RPE。

### 11.5 循环

| 界面操作 | AST | DSL |
| --- | --- | --- |
| 添加循环 | 新建 `RepeatBlock` | `Nx(...)` |
| 修改次数 | 修改 `repetitions` | 修改 `N` |
| 循环内添加步骤 | 写入 `segments[]` | 括号内增加 `+segment` |
| 嵌套循环 | 子 `RepeatBlock` | `Nx(...Mx(...)...)` |

界面不提供无法序列化的“跳过最后一次恢复”开关。需要该结构时，由用户或编辑器明确构造成 `5x(work+recovery)+work`。

### 11.6 备注

步骤和循环备注映射为 `@note("...")`。编辑器显示普通文本框，序列化器负责引号和反斜杠转义。空备注从 AST 中移除，不输出空 `@note("")`。

## 12. 添加步骤

用户点击“添加步骤”时，先选择：

- 跑步；
- 主动恢复；
- 被动休息。

热身和冷身不是全局步骤选择项，而是阶段位置。用户需要热身或冷身时先添加相应阶段，再在阶段中添加跑步步骤。这避免出现“主训练阶段中的冷身步骤”等矛盾状态。

默认值：

- WU/CD 跑步：10 分钟 E；
- MS 跑步：5 分钟 T；
- 主动恢复：90 秒；
- 被动休息：2 分钟；
- 循环：重复 3 次，内部一个 5 分钟 T 跑步步骤和一个 90 秒主动恢复。

默认值只用于创建草稿，用户保存前可以完整修改。

## 13. 步骤聚焦编辑

### 13.1 跑步步骤

字段顺序：

1. 持续方式；
2. 时间或距离；
3. 主目标类型；
4. 主目标具体值；
5. 可选辅助 RPE；
6. 可选坡度；
7. 可选备注。

### 13.2 主动恢复

字段：

1. 持续方式；
2. 时间或距离；
3. 可选备注。

界面解释：“保持缓慢跑动，用于组间主动恢复；不等同于严格 E 配速训练。”

### 13.3 被动休息

字段：

1. 休息时间；
2. 可选备注。

界面解释：“停止跑步或低活动等待；计入训练总耗时，不产生距离。”

### 13.4 循环

字段：

1. 重复次数；
2. 可选备注；
3. 子步骤列表；
4. 添加子步骤/子循环。

循环为空时可以继续编辑，但整门课程不能保存。

## 14. 结构操作

所有结构操作都以 `segment path` 为目标，调用纯函数返回新的 Workout，不在组件中散落数组索引修改逻辑。

建议 core 或 Web 纯模块提供：

- `insertSegment(workout, parentPath, index, segment)`；
- `updateSegment(workout, path, patch)`；
- `moveSegment(workout, path, targetIndex)`；
- `cloneSegment(workout, path)`；
- `removeSegment(workout, path)`。

约束：

- 不能把循环移动到自身或自己的后代中；
- 不能让阶段或循环在保存时为空；
- 删除最后一个 MS 步骤后保留空阶段并立即显示校验错误；
- 上移/下移只在同一父容器内进行；
- 首版桌面拖拽也只支持同一父容器，跨容器移动通过明确的“移动到”操作完成；
- 复制必须深拷贝后代。

## 15. 新建、编辑、复制和导入

### 15.1 新建

```text
课程库 → 新建课程 → 默认草稿 → 编辑 → 校验 → 保存 → 课程库
```

默认草稿包含当前 DSL 版本、MS 和一个 30 分钟 E 跑步步骤。标题、训练目的和课程备注为空；标题和备注可以保持为空，保存时必须填写训练目的。

### 15.2 编辑

```text
自定义课程 → 编辑 → 深拷贝草稿 → 修改 → 保存/取消
```

取消时原课程保持不变。内置课程没有编辑入口。

### 15.3 复制

```text
任意课程 → 复制 → 深拷贝草稿 → 可选标题增加“（副本）” → 编辑 → 保存
```

复制不会立即写入课程库。原标题存在时追加“（副本）”，原标题为空时继续为空。复制内置课程后 `origin` 变为 `custom`，来源字段可保留“复制自……”说明。

### 15.4 导入

```text
课程库 → 导入 → 粘贴单条 DSL → 解析 → 草稿 → 补充元数据 → 保存
```

导入、复制和新建最终进入完全相同的编辑器状态，不维护三套表单。

### 15.5 在训练日引用课程

课程库不只是收藏夹：训练日的两处入口都能直接引用库里的课程。

```text
训练日 → 编辑课表 → 展开课程库 → 使用此课表 → 继续微调 → 保存
训练日 → 添加训练 → 选择训练内容（可选）→ 创建训练
```

- **替换当天课表**：结构编辑器内的课程库条目提供“使用此课表”，替换后仍可继续编辑，保存写入当天计划；已结束（完成/未进行）的会话保留当时的快照，不跟随变化。
- **追加训练带计划内容**：训练名称可手填；选择课程后自动带出课程标题作为名称（可改），并即时预览“计划内容 · …”。选择“不指定内容”时创建纯粹的临时训练，完成时再记录实际内容。
- **不复制课程本体**：引用只是把课程的结构深拷贝进这次训练，后续改课程不会回写历史训练。

## 16. 保存与错误

保存顺序：

1. 校验课程元数据；标题和课程备注可空，训练目的必须非空；
2. 校验 Workout 结构；
3. 尝试序列化 DSL，验证可表达性；
4. 再解析序列化结果，验证结构往返；
5. 写入 localStorage；
6. 更新响应式课程列表；
7. 显示成功提示并返回课程库。

如果任一步失败：

- 草稿保留；
- 不更新原课程；
- 不返回课程库；
- 页面聚焦第一个错误；
- 结构错误同时在对应阶段/循环卡片上显示。

## 17. 响应式与可访问性

### 17.1 断点策略

- 宽屏：课程信息与预览并排，结构树与聚焦编辑面板并排；
- 中等宽度：课程信息和预览上下排列，编辑面板保持右侧或下方；
- 窄屏：单列结构，聚焦编辑使用全宽覆盖层，底部操作固定；
- 不按设备 UA 分支，只按可用宽度布局。

### 17.2 键盘与读屏

- 所有拖拽操作有按钮等价路径；
- 步骤菜单、展开按钮和阶段标题有明确可访问名称；
- 循环结构使用语义化列表和层级说明；
- 焦点进入聚焦编辑时移动到标题，关闭后回到原步骤卡片；
- 删除确认关闭后焦点回到合理位置；
- 错误摘要链接到具体字段；
- 色块附带文本标签，不以颜色独立表达强度。

## 18. 视觉方向

采用“训练控制台”式浅色视觉：

- 页面背景使用低对比暖灰，课程卡片保持清晰白色表面；
- Daniels 强度色作为窄边、预览图和标签，不大面积铺满；
- 循环容器使用结构边框和轻微底色建立层级；
- 主操作使用统一品牌主色，危险操作只在确认点使用红色；
- 数值和单位采用稳定对齐，便于快速扫描；
- 动效只用于展开、选中和结构移动反馈，不使用干扰阅读的持续动画。

## 19. 强度 ↔ 配速展示口径

### 19.1 为什么要有这个开关

课程全部以丹尼尔斯强度（E/M/T/I/R/ST）为第一语言：DSL、AST、颜色、编辑控件都用档位。
但跑者在训练现场需要的是「这次该跑多快」——同一个 `@T` 在不同人身上是不同配速。
展示层因此提供口径切换：把档位换算成本人的配速区间。

这不是第二份事实来源，只是同一份 AST 的另一种投影：

| 层 | 保存的东西 | 说明 |
| --- | --- | --- |
| Workout AST / DSL | `@T`、`@I` 等强度档位 | 唯一事实来源；切换口径不改变 AST，也不写回 DSL |
| 能力（Fitness） | 阈值配速或 VDOT | 换算基准，来自「我的」 |
| 展示 | 档位文案或配速文案 | 由 core 的展示函数即时换算，不落库、不进课程数据 |

### 19.2 两种口径

| 位置 | 强度口径 | 配速口径（阈值 4:00/km 为例） |
| --- | --- | --- |
| 结构树步骤 | `20 分钟 · 乳酸阈配速（T）` | `20 分钟 · 3:45–4:00/km（T）` |
| 循环摘要 | `3 × （8 分钟 T + 90 秒恢复）` | `3 × （8 分钟 T 3:45–4:00/km + 90 秒恢复）` |
| 结构预览提示 | `8 分钟 T` | `8 分钟 T 3:45–4:00/km` |
| 课表文字（训练周/训练日） | `20min@T` | `20min@T · 3:45–4:00/km` |

规则：

1. 配速口径**保留档位字母**——配速是叠加信息，强度身份不因换口径而消失；
2. E、M 标注「估算」：原书只有 6 秒规则精确定义 T/I/R，E/M 是估算区间；
3. 自定义配速目标（`@P4:45-5:00/km`）、心率、RPE 不参与换算：它们本身就是明确目标；
4. **ST 没有配速档位**（跨步跑按全力短距离进行）：配速口径下仍显示强度标签，不伪造配速；
5. 尚未建立能力时同样回退到强度标签，界面说明原因，不猜配速。

### 19.3 开关位置与持久化

- 开关出现在课表展示处：课程库、训练周、训练日的页面头部；
- 只有一个全局偏好，切换后所有页面一起变：localStorage `tfm:display-prefs:v1` 的 `targetDisplayMode`；
- 默认值为 `pace`（配速）：与训练日既有文案一致，课程库因此默认直接看到本人配速；
  想只看 DSL 的强度字母时切到 `zone`，选择会被记住；
- 编辑器（步骤列表、步骤聚焦编辑）始终按强度编辑：那里改的是 DSL 语义，不是展示；
- 课程库卡片、课程编辑预览、训练周、训练日共用同一份 core 展示函数，不各自拼配速文案。

### 19.4 DSL 的两种写法（档位写法 / 配速写法）

展示口径决定「课表怎么读」，写法决定「DSL 怎么写」。两者一一对应，因此课程卡片的 DSL 区提供同一组二选一开关：

```text
写法  ( 强度版 ) ( 配速版 )   按当前能力换算成明确配速（E、M 为估算）
WORKOUT/1
TITLE:阈值课
GOAL:乳酸阈能力
MS:6x(8min@P3:45-4:00/km+90s@jog)
                                        [复制 DSL]
```

| 写法 | 目标写法 | 版本行 | 适用 |
| --- | --- | --- | --- |
| 档位写法（强度版） | `8min@T` | `WORKOUT/1` | 长期交换：与个人能力无关，谁导入都是同一份课表，也是规范往返口径 |
| 配速写法（配速版） | `8min@P3:45-4:00/km` | `WORKOUT/1` | 阅读与执行：按当前能力换算出「这次该跑多快」 |

两种写法都在冻结版本 `WORKOUT/1` 的语法之内，**没有新增版本**。规则：

1. 默认写法跟随全局展示口径（§19.3）：看到配速，复制到的就是配速写法；也可以随时手动切换，切换只影响这一份文本；
2. 投影是**单向**的：只有含档位的课表才提供配速写法。`@P4:45-5:00/km` 本身就是「明确配速」，
   反推档位会凭空发明训练意图，因此明确配速在任何写法下都保持原样，课程卡片也不再显示切换开关；
3. 没有能力时不伪造配速：配速写法退回档位写法并在开关旁说明原因；
4. ST、心率、RPE 目标无法换算，两种写法下保持一致；换算结果越界（不在 90–900 秒/公里、快端不小于慢端）时同样保持档位；
5. 配速写法是**派生、非往返**的：它导入回来是明确配速，不再是原来的档位。需要长期交换时用档位写法；
6. 复制按钮的提示写明复制的是哪一版（「强度版 DSL 已复制」/「配速版 DSL 已复制」），避免把派生写法当成事实来源。

导入、导出与两条写法的完整规则见 §6.7 与 `packages/core/src/dsl/pace-projection.ts`；
语法事实来源始终是冻结规范 `spec/dsl/v1/workout-dsl-v1.md`。

## 20. 交互测试与验收

### 20.1 组件测试

- 课程卡片默认不展示 DSL；
- 展开后正确展示 WU/MS/CD 和嵌套循环；
- 内置和自定义课程显示正确操作；
- 导入错误保留原文并显示行列；
- 导入配速写法后提交的是含明确配速的课程（不会被反推成档位），摘要出现对应说明；
- 含档位的课程卡片显示写法开关，只有明确配速的课程卡片隐藏开关；
- 新建、复制、导入不会在保存前写存储；
- 步骤类型切换只显示合法字段；
- 被动休息没有距离选项；
- 混合单位预览不伪造比例；
- 大循环预览不会创建无界 DOM；
- 上移、下移、复制、删除修改正确路径；
- 嵌套循环不能移动到自身后代；
- 保存失败保留草稿；
- 保存成功刷新列表。

### 20.2 浏览器验收

- 桌面端新建一条包含 WU、嵌套循环、恢复、休息和 CD 的课程；
- 移动端完成相同课程的步骤编辑；
- 复制内置课程后修改副本，内置课程不变；
- 编辑自定义课程并刷新验证持久化；
- 导入单条 DSL、补充元数据并保存；
- 导出后重新导入，结构与展示一致；
- 使用键盘完成步骤展开、移动和保存；
- 训练日从课程库替换当天课表，并追加一次带课程内容的训练；
- 在长课程和十层边界循环下页面仍可操作。

### 20.3 展示口径验收

- 课程库默认按配速展示，T、I 等档位显示为当前能力的配速区间，并保留档位字母；
- 切到「强度」后配速文案消失、只留档位，刷新后仍保持选择；
- 训练周与训练日的课表文字跟随同一开关；
- 尚未建立能力时课程库不出现配速文案，开关给出提示；
- 切换口径不改变课程 DSL：导出、复制、编辑的结果与切换前一致。

### 20.4 写法验收

- 从含档位的课程导出配速写法，文本里的目标变成明确配速 `@P3:45-4:00/km`，版本行仍是 `WORKOUT/1`；
- 导入配速写法 `MS:6x(8min@P3:45-4:00/km+90s@jog)` 后，课程数据里是明确配速，不会被反推成档位；
- 课程卡片的写法开关在强度版与配速版之间切换：配速版是明确配速写法，强度版只有档位；用当前能力导出配速版后重新导入，结构与汇总保持一致；
- 明确配速课程（如 `MS:12km@P4:45-5:00/km`）不显示写法开关，也不产生档位；
- 换了能力以后重新导出配速写法，配速随能力更新；
- 尚未建立能力、ST 步骤或换算越界时，该步骤退回档位写法，界面说明原因。

## 21. 完成定义

- DSL 文档中的每一种结构都有对应编辑控件和只读展示；
- 编辑器中的每一种可保存状态都能唯一序列化为 DSL；
- 课程卡片、结构预览、递归步骤树和编辑器读取同一个 Workout AST；
- 不存在只保存在 UI、localStorage 派生字段或 DSL 文本中的训练语义；
- 新建、编辑、复制、删除和单条导入形成完整闭环；
- 展示口径（强度 ↔ 配速）是只读投影：不新增训练语义，不进 DSL，不落库；
- DSL 的配速写法是档位课表的单向派生投影：导出配速版按当前能力重算，导入配速版得到明确配速、不反推档位；
- 桌面端与移动端功能等价；
- 自动化测试和浏览器验收覆盖完整闭环。
